# 安全威胁模型 v1

**状态：提议。**范围：v0.3 新增的攻击面——设备通道、入网、Broker、沙箱里的 Pi 与生成代码、记忆与证据包、硬件采集。v0.2 与 `validation-followups.md` 里的 P0 清单（证书生命周期、依赖漏洞扫描等）继续有效，本文不重复。

## 1. 资产与分级

| 资产 | 说明 | 等级 |
|---|---|---|
| 设备私钥与证书 | 设备身份 | 最高 |
| LLM、数据库、Hindsight 凭据 | 只在 Runtime 与受控网关 | 最高 |
| 生物特征数据（心率、血氧） | 敏感健康数据 | 高 |
| 媒体数据（照片、音视频） | 含他人隐私 | 高 |
| 用户记忆与进化记忆 | 个人习惯与需求 | 高 |
| 技能包与注册表 | 决定系统将执行什么 | 高 |
| 作业、会话、审计记录 | 可能含个人信息 | 中 |

## 2. 信任边界

```text
[物理世界/他人] ─不可信文字与画面─► [设备] ─mTLS─► [Runtime（可信）] ─UDS/stdio─► [沙箱（不可信）]
                                                        │
                                                        └─► [Hindsight、模型提供方、对象存储]
```

- 设备被视为**受限可信**：身份可信，但它读到的文字内容、传感器值不可信，且它可能被攻破或遗失。
- 沙箱里的 Pi 与生成代码被视为**不可信**：它们可能被提示注入、被依赖投毒，或自己写出恶意代码。
- 记忆召回结果与证据包里的外部文字是**不可信数据**，只能作为参考，不能当指令。

## 3. 威胁与缓解

| 编号 | 威胁 | 缓解 | 验证 |
|---|---|---|---|
| T1 | 物理世界提示注入：OCR、ASR、摄像头文字进入记忆或证据包，诱导生成恶意技能或误导技能行为 | 外部文字一律标为不可信数据，放在数据区，不进指令位；证据包脱敏；生成的代码只在无网络沙箱运行；静态检查加能力白名单；试用护栏 | 红队用例：招牌上写“忽略之前的指令”，验证不会改变生成提示 |
| T2 | 沙箱逃逸：容器共享宿主内核，而 Pi 会运行 LLM 写的 bash | 非 root、只读根文件系统、seccomp、资源限制；产品化前升级到 gVisor 或 microVM；沙箱无外部网络 | 沙箱攻防测试（读宿主路径、探测网络、fork 炸弹） |
| T3 | Broker 的“代理人混淆”：技能借 Broker 以别的设备身份行事 | 令牌绑定设备与作业；每作业一个套接字；Broker 只信令牌与套接字身份 | 用 A 作业的令牌访问 B 设备的能力，必须失败 |
| T4 | npm 供应链：依赖或 Pi 包被投毒 | 镜像预装并固定版本；`--ignore-scripts`；运行时禁止 `pi install`；依赖白名单与扫描；不装第三方 Pi 包（Hindsight 集成优先自写极简客户端） | 镜像构建时对依赖树做差异审计 |
| T5 | 遥测或自动联网导致外泄 | `PI_TELEMETRY=0`、`--offline`；沙箱无外部网络 | 抓包验证容器没有对外连接 |
| T6 | 密钥泄露 | LLM 密钥只在受控网关；设备密钥放安全存储；数据库凭据永不进沙箱；日志脱敏 | 扫描镜像、环境变量与日志中的密钥特征 |
| T7 | 成本失控与拒绝服务 | 受控网关按作业限 token 与时长；每设备并发作业数限制；入口限流；音视频有界队列 | 压测：恶意设备高速发送，系统不崩溃且其他设备不受影响 |
| T8 | 会话与评测数据里的个人信息长期留存 | 确认或过期后清理会话；评测用例有 `retain_until`；日志不记录原始媒体与生物特征 | 清理流水线与孤儿扫描的测试 |
| T9 | 服务端被攻破后下发恶意采集命令 | 设备端自己强制采集指示、时长上限、物理静音；命令带 `indicatorRequired` | 设备一致性测试：违规命令被拒绝 |
| T10 | 设备遗失或被盗 | 管理员侧吊销证书，断开连接；恢复出厂清除密钥；重新入网需新令牌 | 吊销后重连必须失败 |
| T11 | 入网令牌被截获或爆破 | 令牌单次、几分钟过期、库里只存摘要；入网接口限速并审计；设备端固定 CA | 令牌重复使用、过期、错误令牌测试 |
| T12 | 伪造或重放设备消息 | `device_id` 只来自证书；信封里有序号与时间窗；幂等键；Schema 校验 | 伪造 `device_id`、时间窗外、重复序号的用例 |
| T13 | 技能越权：用户未授权的硬件被使用 | 新硬件权限永不自动授予；生物特征单独授权；Broker 每次校验授权 | 试用技能请求未授权硬件，必须失败并提示 |
| T14 | 生成的技能把个人信息写进代码或 manifest | manifest Schema 中 `storesPersonalData` 恒为 false；静态检查扫描；审查者角色专查硬编码个人信息 | 构造含个人信息的候选，必须被拒绝 |
| T15 | 并行候选或审查者被污染（一个角色改了另一个角色的文件） | 每候选独立目录；审查者只读挂载；合并只经 Runtime | 审查者写文件的尝试必须失败 |
| T16 | Hindsight 召回被攻击者操纵：旧的恶意记忆长期影响行为 | 召回内容标为不可信；不触发工具调用；记忆来源与时间可审计；用户可查看与删除 | 注入恶意记忆后验证行为不受指令影响 |
| T17 | 误导性的健康提示 | 不做诊断；措辞为提示；输出带置信度；缺数据源时明确说明不可靠 | 内容评审与用例 |

## 4. 密钥管理

- 设备：私钥在安全芯片或 Android Keystore 中；证书有有效期并能在 mTLS 通道上续期；吊销立即断开连接。
- Runtime：LLM、Hindsight、数据库凭据来自环境或密钥管理服务，不进镜像、不进日志；受控网关独占 LLM 密钥。
- 开发 CA 与正式 CA 分开；正式构建不信任开发 CA，也不关闭证书校验。

## 5. 日志与审计

- 日志记录元数据与哈希，不记录原始音视频、生物特征序列、提示词原文和个人记忆内容。
- 作业事件、Broker 调用、技能执行、吊销与入网操作都有审计记录。
- 所有拒绝与异常（Schema 校验失败、令牌错误、权限拒绝）只记录摘要，不记录载荷。

## 6. 数据保留

| 数据 | 保留 |
|---|---|
| 原始音视频 | 默认不落库，只保留衍生结果 |
| 生物特征原始序列 | 不落库，记忆里只存摘要和趋势 |
| Pi 会话与工作区 | 确认后清理；未确认一周后清理 |
| 评测用例 | 脱敏，有 `retain_until` |
| 技能包与注册表 | 随设备；用户可删除 |
| 进化记忆库 | 用户私有，可查看、导出、删除 |

## 7. 事件响应要点

1. 发现设备遗失或疑似入侵：吊销证书，断开连接，标记设备 `BLOCKED`。
2. 发现某技能行为异常：暂停技能（`PAUSED`），回退到上一个 `ACTIVE` 版本，审计其执行记录。
3. 发现沙箱镜像存在漏洞：停止新作业，回收运行中的作业，更新镜像后重新验证。
4. 发现记忆被污染：隔离相关记忆，评估已生成技能，必要时重新验证。
